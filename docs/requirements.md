# solar-lag-3d 要件定義・アーキテクチャ

夏至（昼が最も長い日）と日没最遅日のズレを 3D で可視化し、地軸の傾き・離心率・近日点の位置・緯度を変えて「どういう条件ならズレないか」を思考実験・比較するシミュレーター。

既存の天文ライブラリに頼らず、任意パラメータから自前で計算する。

> 本書は設計インタビュー（2026-10-02）の確定事項をまとめたもの。括弧内の Qn はインタビューの質問番号。Q34 以降は、本書のマルチエージェントレビューで見つかった問題を受けて決めた。将来の課題は [backlog.md](./backlog.md) を参照。
>
> 本書中のズレの日数などの数値は、レビュー時に試算した参考値である。正式な値は実装後にテストで確定させる。**テストの期待値として流用しないこと。**

---

## 1. 目的とユーザー

- 対象：天文好き・理系向けの**公開ツール**（Q1）
- 自分用の自由度（細かいパラメータ操作、数値表示）を保ちつつ、URL で条件を共有できる
- ガイド付きの解説など一般向けの要素は、後から重ねられるようにしておく

## 2. コア体験

### 2.1 3D と 2D グラフの連動（Q2, Q30）

ズレの正体は「均時差」と「昼の長さの変化」の重ね合わせで、3D を眺めるだけでは見えにくい。そこで 3D ビューと次の 2D グラフを**同じ日付で連動**させる。

- 日の出・日没・南中時刻の年変化グラフ
- 均時差グラフ

日付スライダー、グラフ上の日付カーソル（ドラッグ可）、3D ビューは常に同じ日付を指す。「▶再生」で日付を自動送りする。

### 2.2 A/B 比較（Q15, Q28, Q35, Q44）

パラメータの組を 2 つ（A と B）持ち、たとえば「現在の地球」と「真円軌道」を並べて比べる。

- 各セットは**すべてのパラメータ**（ε, e, ϖ, 緯度, h₀）を独立に持つ
- 2D グラフでは A/B を**それぞれの夏至の瞬間を原点 0 にそろえて**重ね描きする（Q35）
  - 日付カーソルは「夏至から +X 日」という相対位置を共有し、A/B はそれぞれ自分の夏至の X 日後の状態を表す
- 3D ビューは A/B のどちらか一方を表示する

| 項目 | 仕様（Q44） |
|---|---|
| B の有効化 | 初期状態は A のみ。「＋ 比較を追加」で B を作り、A の値を複製する |
| B の削除 | B のタブの ✕ で削除し、A のみの表示に戻る |
| プリセットの適用先 | パラメータパネルで選択中のタブ |
| パラメータのタブと 3D のタブ | 連動させる |
| 結果欄 | A と B を 2 列に並べ、その下に差（B − A） |
| プリセットの値を変更したとき | プリセット欄の表示を「カスタム」に切り替える |
| 「B の緯度を A に揃える」 | ボタンを置く |

- 内部のデータ構造は最初から配列（`sets: Params[]`, `activeIndex`）で持ち、A/B は表示上の名前とする。将来 N 個に拡張できる

### 2.3 結果表示（Q17, Q31, Q36〜Q38, Q42, Q43）

至点の前後で起きる 4 種類のズレを出す。定義は §3.4 を参照。

| 基準の至点 | 現象 |
|---|---|
| 夏至 | **日没最遅日**（主役） |
| 夏至 | 日の出最早日 |
| 冬至 | 日没最早日 |
| 冬至 | 日の出最遅日 |

- どれを表示するかはユーザーが選べる。既定は全部表示で、日没最遅日を大きく出す
- 表示例：「+X.X日（6月XX日ごろ）」。小数日と参考の暦日付を併記する
- 結果の種類に応じて表示を変える（Q37, Q38）

| エンジンの結果 | 表示例 |
|---|---|
| `peak`（曲線に山がある） | 「+X.X日（6月XX日ごろ）」。至点の前後半年の範囲にほかの山もあれば「ほかにも山があります」と注記 |
| `polarBoundary`（白夜・極夜で途切れる） | 「白夜の直前（夏至の −X.X日）が最遅」 |
| `undefined`（理由付き） | ε=0 のとき「至点が存在しない（昼の長さが一定）」など |

- ε が 0 に非常に近い（ただし 0 ではない）ときは数値を出し、「昼の長さの変化が小さいため、ズレはほぼ均時差だけで決まります」と注記する（Q38）
- **参考値**：「夏至の日の昼の長さ」と「1 年で最長の昼の長さ」を並べ、その差がほぼゼロであることを示す。ズレの原因が昼の長さではなく日没時刻の側にあることの裏付けになる（Q24, Q42）
- **南半球のラベル**：「夏至（12月至点）」「冬至（6月至点）」のように括弧で補足する。英語では "summer solstice (December)"（Q43）

### 2.4 プリセット（Q5, Q27）

| 名前 | ε | e | ϖ | ねらい |
|---|---|---|---|---|
| 現在の地球 | 23.44° | 0.0167 | 283° | 基準 |
| 真円軌道 | 23.44° | 0 | （保持） | e=0 でもズレが残る（地軸の傾きによる成分） |
| 近日点が夏至の位置 | 23.44° | 0.0167 | 90° | 近日点の位置でズレが変わる |
| 近日点が冬至の位置 | 23.44° | 0.0167 | 270° | 現在の地球（283°）に近い。真円軌道と比べると、離心率が夏側のズレを縮めていることがわかる |
| 傾き0 | 0° | 0.0167 | 283° | 夏至そのものが消える（結果は `undefined`） |
| 火星風 | 25.19° | 0.0934 | **251°** | 離心率が大きい例。日没最遅日が夏至より**前**になる（自転・1 年の長さは地球のまま） |
| 極端な傾き | 60° | 0.0167 | 283° | 中緯度でも白夜・極夜が起き、ズレが白夜の境界で決まる |

- 緯度と h₀ はプリセットに含めず、現在の値を維持する。緯度の既定値は東京（35.68°N）
- 火星の ϖ は、火星自身の春分点から測った近日点通過時の太陽黄経 Ls ≈ 250.9° を使う（J2000 黄道での日心近日点黄経 336° ではない）
- 「極端な傾き」で白夜になる条件は φ > 90° − ε − |h₀|。h₀ = −0.833° なら緯度 29.2° 以上で白夜になる
- e = 0 のとき、ϖ のスライダーは無効化するが値は保持する。近日点・遠日点のマーカーは隠す（e = 0 なら ϖ は計算結果に影響しない）（Q44）

## 3. 計算モデル

### 3.1 パラメータと範囲（Q3, Q7, Q26, Q39, Q40）

| パラメータ | 範囲 | 既定値 | 備考 |
|---|---|---|---|
| 地軸の傾き ε | 0°〜**89.9°** | 23.44° | 90° ちょうどは至点で赤経が定義できなくなるため除外 |
| 離心率 e | 0〜**0.5** | 0.0167 | 0.5 を超えると 1 日刻みの計算の前提が崩れる。0.9 までの拡張はバックログ |
| 近日点の位置 ϖ | 0°〜360°（循環） | 283° | 下記の定義を参照 |
| 緯度 φ | **−89.9°〜+89.9°** | 35.68° | 極点ちょうどは日没時刻の式が 0 除算になるため除外 |
| 日没高度 h₀ | −2°〜+2° | −0.833° | 詳細設定。プリセット「地球標準（−0.833°）」「幾何（0°）」 |

- **ϖ の定義**：その惑星自身の春分点から測った、**近日点通過時の太陽の黄経**（地心）。UI では「近日点通過時の太陽黄経」と表記する。地球の 283° は、文献でよく使われる日心近日点黄経 103° に 180° を足した値にあたる
- **h₀ の注記**：h₀ は太陽中心の高度として扱う。−0.833° は 1 AU での太陽の視半径と地球の大気差を前提にした値で、e を大きくして太陽との距離が変わっても視半径の変化は考えない
- 自転周期と 1 年の長さは地球に固定する。1 年 = 365.2422 平均太陽日

### 3.2 時刻系と均時差（Q9）

- **地方平均時**で表示する。観測者は標準時の子午線上にいるとみなし、経度は入力しない（経度は全体に一定値を足すだけで、ズレの日数に影響しないため）
- 平均太陽は、平均黄経 L = M + ϖ（M は平均近点角）で赤道上を一様に進む
- 太陽黄経 λ = ν + ϖ（ν は真近点角）
- **均時差** E = (L − α) / 15°［時］。α は L に最も近い値を取る（±12 時間で折り返さず、連続になるよう補正する）
- 真の南中時刻 = 12h − E

### 3.3 時刻座標と暦（Q8, Q34, Q35）

- 内部の時刻 t は、**春分の瞬間からの経過日数**（平均太陽日）に統一する
- 参考の暦日付：平年の 3 月 20 日 0:00 を t = 0 とし、UTC 固定で整形する（利用者の環境のタイムゾーンで 1 日ずれないように）。グラフの目盛りと結果欄は同じ換算関数を使う
- 横軸の主軸は「夏至からの日数」。各セットの夏至の瞬間を原点とする（§2.2）

### 3.4 定義（Q10, Q24, Q34, Q36〜Q38, Q43）

- **夏至**：太陽黄経 λ = 90° の瞬間。緯度 < 0 のときは λ = 270° の瞬間（12月至点）を夏至とする。冬至はその反対側の至点
- **日没・日の出**：太陽中心の高度が h₀ になる瞬間（Q7）
- **ズレ**：基準の至点の瞬間から、極値となる日没（日の出）の**瞬間そのもの**までの経過日数（Q34）

| ズレの種類 | 基準の至点 | 探す極値 |
|---|---|---|
| 日没最遅日 | 夏至 | 日没時刻の極大 |
| 日の出最早日 | 夏至 | 日の出時刻の極小 |
| 日没最早日 | 冬至 | 日没時刻の極小 |
| 日の出最遅日 | 冬至 | 日の出時刻の極大 |

- **極値の選び方**：至点の前後半年の範囲で、至点に**最も近い**局所極値を採る。範囲内にほかの局所極値もあれば、結果に件数を付けて返す（Q36）
- **白夜・極夜で途切れる場合**：曲線が白夜・極夜の境界に向かって単調に伸びて途切れるときは、`polarBoundary` として境界の瞬間を返す（Q37）
- **ε = 0 のとき**：4 種類とも `undefined`（理由：至点が存在しない）を返す。しきい値は設けない（Q38）
- **参考値**：夏至の日の昼の長さと、1 年で最長の昼の長さ（Q42）

### 3.5 計算方法（Q25, Q39）

1. 平均近点角 M → ケプラー方程式（Newton 法。初期値 E₀ = M、|ΔE| < 1e−12 で収束判定、反復回数に上限を設ける）→ 真近点角 ν → 太陽黄経 λ
2. λ, ε → 赤緯 δ、赤経 α → 均時差 E
3. 時角 H：cos H = (sin h₀ − sin φ sin δ) / (cos φ cos δ)
4. 日没時刻 = 12h + H / 15° − E。**日没の瞬間の δ と E で再計算する反復**を、変化が 1 秒未満になるまで行う（反復回数に上限を設ける）
5. 時刻は 24 時で折り返さない連続値として扱う
6. 1 日刻みの値から極値の近くを特定し、黄金分割探索などで連続値の極値を求める

- |cos H| > 1 のとき（白夜・極夜）は、エラーではなく正当な結果として返す（Q11）

### 4.2 縮尺と座標（Q21）

## 5. 共有と状態（Q5, Q29, Q32, Q41）

URL のクエリに次を含める。値には名前を付けて並べる。

| キー | 中身 | 例 |
|---|---|---|
| `a`, `b` | 各セットのパラメータ（`b` の有無が B の有効化を表す） | `a=eps23.44_e0.0167_w283_lat35.68_h-0.833` |
| `d` | 日付カーソル（夏至からの日数） | `d=8.1` |
| `v` | 3D で表示中のタブ | `v=a` |
| `lang` | 表示言語 | `lang=ja` |
| `show` | 表示するズレの選択（既定から変えたときだけ） | `show=ss,sr` |

- **バージョン番号は入れない**。知らない名前の値は無視し、意味を変えるときは名前を変える（Q41）
- 読めない値は既定値に戻し、範囲外の数値は範囲内に収める（ϖ は 360° で割った余り）
- URL に書く数値の桁数を決め（例：ε は小数 2 桁、e は小数 4 桁）、読み込みと書き出しで値が変わらないことをテストする
- URL への書き込みは `history.replaceState` で行い、200〜500 ms 間引く。再生中は書き込まない
- 表示言語の優先順位：URL の `lang` > 保存済みの設定 > ブラウザの言語
- 3D カメラの角度は含めない

## 8. アーキテクチャ

```
src/
  engine/   純粋なTypeScript。React に依存しない
            orbit（ケプラー方程式）→ sun（黄経・赤緯・均時差）
            → events（日の出・日没、反復計算）→ extrema（極値探索）
  store/    Zustand。パラメータの配列、日付、表示状態。URL と同期する
  ui/       パラメータパネル、結果欄、レイアウト
  charts/   SVG グラフ
  scene/    react-three-fiber。差し替え可能な視点
  i18n/     ja, en
```

### 8.1 計算エンジンの API

- `computeYear(params, body) → YearResult`：1 年分の曲線と 4 種類のズレ
- `sceneState(params, body, t) → SceneState`：その瞬間の 3D の状態（太陽と惑星の位置、地軸の向き、自転の位相など）
- `params = { epsilon, e, varpi, phi, h0 }`
- `body = { yearDays, siderealDayRatio }`：R1 では地球の値で固定する。将来、地球以外の惑星（バックログ）に拡張するための入口
- ズレの結果は判別可能な型で返す：`{ kind: 'peak', ... } | { kind: 'polarBoundary', ... } | { kind: 'undefined', reason }`
- 座標系：エンジンは黄道座標系（右手系、距離の単位は AU）で計算する。Three.js の座標系への変換は scene/ 側の 1 か所だけで行う
- **計算エンジンはフレームワークから完全に分離する**。UI の選択を後から変えても、計算部分はそのまま残る

### 8.2 性能

- `YearResult` はパラメータの値をキーにして再利用し、日付が変わっても計算し直さない
- 日付カーソルはストアの別の区画に置く。グラフの曲線は再利用し、カーソルの要素だけを動かす
- 3D は react-three-fiber の `useFrame` や Zustand の購読を使い、React の再レンダーを通さずに更新する
- 目標：パラメータのスライダーをドラッグ中も 60 fps を保つ

## 9. 品質保証（Q12）

### 9.1 既存ライブラリとの照合

- アプリ本体は自前の計算のみ。**テストでは astronomy-engine を答え合わせ用に使う**（devDependencies のみ）
- 照合の手順：
  - 基準年を 1 つ決め、その年の ε, e, ϖ をモデルに与える
  - 比較は、同じ太陽黄経 λ の時点どうしで行う
  - 観測者は東経 135° に置き、UTC から地方平均時に換算する
  - 日の出・日没は astronomy-engine の `SearchAltitude`（中心高度 = h₀）で求め、高度の定義をそろえる
  - 均時差は astronomy-engine の時角と恒星時から組み立てる
- 許容誤差は、実装の初期に実測して数値で確定させる（目安：日の出・日没、均時差とも ±30 秒）

### 9.2 性質ベースのテスト（fast-check）

地球以外のパラメータは、物理的に必ず成り立つ性質で検証する。

- ε = 0 かつ e = 0 なら、均時差は常に 0、昼の長さも常に一定
- ε = 0 なら、日没と日の出の時角 ±H は常に一定（e > 0 では時計で測った昼の長さは数秒揺れるので、「昼の長さが一定」は性質にしない）
- 緯度の生成範囲は ±89.9° の内側に限る

### 9.3 CI

- PR ごとに型チェック、Biome、テスト、**ビルド**を実行する
- main ブランチへの統合で GitHub Pages に公開する
- ブラウザでのテスト（E2E）は当面入れない
